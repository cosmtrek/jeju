# Design Context — Jeju website

## Product

Jeju is a local-first agent runtime. The website (`website/`) is a static Astro
landing page for its first-party writing catalog: four bounded DeepSeek-backed
writing workers (review / polish / rewrite / translate) that an orchestrating
coding agent (Codex, Claude Code) delegates to. The `jeju-writing` skill is a
router, not a fixed pipeline: simple translation/polish/rewrite requests go
straight to the matching worker; only review, publish-readiness checks, and
end-to-end revision start with the article-editor's structured review.

## Target audience

Developers who write Chinese prose (blogs, docs) and already live inside a
coding agent. They are terminal-native, skeptical of agent hype, and care about
cost, reproducibility, and being able to audit what an agent actually did.

## Use cases

1. Decide in one screen whether the "subordinate agent" model is worth trying.
2. Copy three commands: install the skill, add the packages, run a review.
3. Verify trust: see what evidence a run leaves (trajectory, report, digest).

## Positioning (fixed narrative, from the project plan)

"Others hand your agent a document of tips. Jeju hands it a subordinate —
cheap, focused, stable in behavior, and it files a report when done."
(别人给你的 agent 一份经验文档，Jeju 给你的 agent 一个下属——便宜、专注、行为
稳定、干完留档。) Differentiators: cost split (expensive orchestrator, cheap
executor), fixed manifest config, enforced policy/workspace boundary,
trajectory evidence.

## Brand personality / tone

Sharp, engineering-first, with an island identity — "harbor workshop" rather
than generic dark dev-tool. English by default; trust through precision,
evidence, and restraint. Personal project by cosmtrek (Ricko Yu, author of
`air`) — identity is part of the trust story ("dogfooded, not demoed").

Aesthetic direction (2026-07 redesign): light-first "paper" theme — warm paper
background `oklch(96.5% 0.01 85)` with basalt ink text `oklch(24% 0.015 60)`
(all neutrals tinted toward the tangerine hue). Hallabong tangerine in two
roles: text-safe terracotta `oklch(55% 0.145 45)` for section indexes,
YAML/JSON keys, deny states, wordmark dot; brighter fill `oklch(67% 0.165 48)`
for the CTA and selection. Sea teal (`oklch(48% 0.09 195)` on paper) only for
allow/verified states. The hero "run replay" terminal is the one dark object
on the page — it re-declares the palette tokens on `.replay` (basalt
`oklch(21% 0.012 55)` bg, lighter orange/teal inside) and floats with a soft
shadow. Type: Bricolage Grotesque (display + body, opsz 12..96) + Sometype
Mono (labels/code). Hairline dividers, 2–5px radii, uppercase mono
micro-labels. Jeju-island motif: generated Hallasan contour lines (seeded,
build-time) in the hero background with a "1947" summit marker; same motif in
og.png (light) and favicon.svg (kept dark, badge-like). Further island
elements, used sparingly: contour-ring badges before section indexes, a dashed
map-route pipeline diagram (manifest → compile → run → trajectory → view), a
rotated circular "EVIDENCE FILED · SHA256 VERIFIED" harbor stamp on the mock
report card, and a wavy coastline divider with island coordinates above the
footer. The footer is a minimal colophon: "Make better products. — Ricko Yu" —
the reusable personal sign-off across all of Ricko's products (name links to
rickoyu.com, set in fg weight 600 as the signature) — plus exactly three
links: GitHub, Docs, Registry. No seal, no avatar, no mascot; keep the footer
this small. Page order: hero (stacked: copy, then a ~920px replay terminal) →
what-it-is → pipeline/report → why-a-runtime → quickstart (with "→ what
happens" mono notes under each command) → build-your-own (jeju-agent-builder,
the base authoring skill: ask → 4-step loop → bundle tree) → writing team
(framed as the builder loop's first product) → registry. The replay animation (typed request → routing → policy allow/deny →
JSON verdict → evidence line) renders the finished run statically under
reduced-motion/no-JS. Never
gradients, glows, or purple/cyan. Chinese appears only as authentic working
material (a sample request), never as UI chrome. Entry point is `npx skills
add` + a natural-language prompt; jeju CLI commands appear in Quickstart
step 3 and "Under the hood".

## Constraints

- Astro static single page in `website/`; no runtime UI, no dynamic backend.
- Package data must come from `src/data/catalog.generated.json` (generated).
- Hero must keep the three-command quickstart; evidence section must show a
  findings sample; links section must point to GitHub/docs/blog/registry.
- All install/run examples use `jeju:` registry references only.
